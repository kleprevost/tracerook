# TraceRook Cloud

TraceRook Cloud serves `api.tracerook.dev`: a TypeScript Cloudflare Worker implementing the `/v1` protocol in [CONTRACT.md](CONTRACT.md). It uses D1 for invitation/account/device digests and categorical provider receipts, and one SQLite Durable Object (`AlphaCoordinator`) for authoritative quota, monthly cost accounting and device-scoped idempotency. There is no mock inference mode in deployable code. Tests inject synthetic upstream replies and never make live provider calls.

## Operator deployment

Requires Node 24+ and npm. Use `npm ci`, `npm run typecheck`, `npm test`. If npm 10's optional-peer resolver rejects the Vitest graph, use `npm install --legacy-peer-deps`; peer versions align in the lockfile. The `sharp` 0.35.5 override fixes the development toolchain's librsvg advisory; the Worker has no runtime npm dependencies.

1. Authenticate Wrangler with the TraceRook Cloudflare account. Keep its existing account on the Free plan; do not upgrade. Create **separate** D1 databases named `tracerook-cloud-staging` and `tracerook-cloud-production` using `npx wrangler d1 create NAME`. Replace only the respective placeholder database UUID in `wrangler.jsonc`.
2. Apply D1 migrations explicitly per environment: `npx wrangler d1 migrations apply tracerook-cloud-staging --env staging --remote`, then production after review.
3. Set separate ≥32-character cryptographically random `AUTH_DIGEST_KEY` values with `npx wrangler secret put AUTH_DIGEST_KEY --env staging` and production. Store a recoverable copy in the operator's secret manager for invitation creation. Changing this secret invalidates all outstanding credentials and invitations.
4. Set `ANTHROPIC_API_KEY` only through Wrangler secret storage, separately for the desired environment, using the TraceRook-owned first-party Console workspace. No client/BYOK keys. Never pass keys on command lines or paste them into logs, checked-in files, or `.dev.vars` destined for git.
5. Confirm current Haiku 5.5 list rates independently. Configure `INPUT_PRICE_MICRO_USD_PER_TOKEN` and `OUTPUT_PRICE_MICRO_USD_PER_TOKEN` in the environment to those positive rates. These are operator-reviewed estimated-cost accounting rates, not a billing integration. Defaults are 0.1 microUSD/input token and 0.5 microUSD/output token, matching [Anthropic Haiku pricing](https://www.anthropic.com/claude/haiku) ($0.10/M input and $0.50/M output for ≤100K prompts). Reconfirm when prices change. Fractional rates are accepted; each reservation/settlement rounds the total estimated microUSD upward. Inference still requires the server secret and explicit enable flag. Haiku 5.5 uses proven one-shot `max_tokens:800`, `output_config.effort:"low"`, structured JSON schema. No beta/fallback routing or automatic retries.
6. Deploy staging with `npm run deploy:staging`, test authenticated operations, and then `npm run deploy:production`. Both environments start with `CLOUD_ANALYSIS_ENABLED:"false"`. Change that explicit flag only after credentials/rates/operational smoke are ready. Health and enrollment do not prove working Claude inference. Connect the production Worker to custom domain `api.tracerook.dev` through Cloudflare's Worker custom-domain configuration; no route or DNS change is assumed by this source.
7. Run `npm run invite -- staging` or production **interactively**. It prompts for the digest secret without echo, executes digest-only SQL using Wrangler D1 CLI, removes its private temporary SQL file, and displays the plaintext one-use invitation once for private delivery. It never persists invitation plaintext. Do not run in recorded terminals or CI. Default expiry is seven days; one redemption creates one account/device. Device tokens expire after 30 days. The operator can add a new digest-only invite for the same account to permit additional devices (maximum three).

Wrangler's `new_sqlite_classes` migration is intentional: SQLite-backed Durable Objects and D1 are supported on Workers Free. No KV, R2, paid DO class, paid observability, external queue, or billing service is provisioned. Free-plan platform request/CPU/storage/D1 quotas still apply; exhausting them may fail requests. Runtime code never attempts an account upgrade. Source maps are not uploaded and Worker observability is disabled. Cloudflare may still retain platform security/access metadata under its own account settings and terms; inspect those settings before launch. No application body/header/key logging is implemented.

## Quotas and abuse limits

Customer quotas and the global spending cap are off: `DAILY_EVALUATION_LIMIT`, `DAILY_INPUT_TOKEN_LIMIT`, `DAILY_OUTPUT_TOKEN_LIMIT` and `GLOBAL_MONTHLY_CAP_MICRO_USD` default to the string `"null"` (uncapped). Set any of them to a nonnegative integer to enforce a limit; all are tested. With inference enabled, Anthropic usage is billed without a software cutoff, so watch the Console.

Abuse protections are always on: the emergency kill switch, invite-only enrollment, request bounds, 120 requests/device/minute, 240 requests/IP/minute, 10 enrollment attempts/IP/minute, two simultaneous analyses per device and three devices per account. IPs are HMAC-derived for short-lived counters and never stored in plaintext.

## Crash and concurrency behavior

A single alpha coordinator serializes short auth/lifecycle and D1 enrollment operations. Bounded request bodies are parsed **outside** that gate, with a three-second upload deadline. Anthropic calls run outside the gate with an abort deadline shorter than the client deadline. Atomic SQLite transactions reserve the account counters and global monthly cost together before any provider call. This guarantees global/account optional caps across multiple Workers, devices and object restarts without eventual-consistency races. The global coordinator is intentionally a small-alpha bottleneck; larger scale needs a documented sharding protocol preserving global reservations, not a drop-in per-account counter.

Reservations conservatively assume at most 16,000 input tokens and 800 output tokens using configured prices. The fixed prompt, schema and bounded projected fields are below the input byte ceiling; usage above those limits is rejected and retains the maximum reservation. On a validated success, actual input/output tokens settle the reservation. All provider failures/timeouts/cancellations/crashes retain the full reservation: whether Anthropic billed cannot safely be inferred. Thus reported actual token usage excludes unknown failed outcomes, while reserved tokens include them. Estimated cost can exceed actual invoiced cost. Reconcile against the Console; no refund is assumed.

Device/request UUID plus canonical payload digest is durable before the provider invocation. Duplicate pending requests return 409; changed body returns conflict; successful duplicates share a cached advisory verdict for at most 600 seconds. Failed/ambiguous/expired replays return `replay_unavailable` and never initiate a second call. The identity ledger is retained 90 days; older UUIDs must never be reused. Approval or host execution decisions are never cached. Rotation invalidates old tokens immediately; a revoked/rotated/deleted principal cannot obtain a late upstream response. Already-sent provider traffic cannot be recalled.

Settlement and a metadata-only D1 receipt outbox commit in one SQLite transaction. D1 outages cannot destroy a valid cached verdict or trigger a second upstream call. The periodic alarm retries receipt writes. Account deletion first durably denies the principal and creates a resumable deletion job, then deletes account-linked D1 and SQLite records; if interrupted, the alarm completes the purge. Global monthly aggregate cost remains without account identifiers.

Cache serving expires strictly at 600 seconds. Alarms preserve the earliest expiry and purge full cached verdicts, account usage after 90 days, receipts after 30 days, invites 30 days after expiry, and IP/rate counters after at most an hour. Physical cleanup is subject to Cloudflare alarm scheduling/outage delays; no raw context is ever in these stores. Account/device digests remain until account deletion. D1 receipt outbox holds only identifiers, actual token counts, timestamps and first-party upstream request-id, never prompt or explanation. Upstream request IDs are restricted operator metadata; customer trace IDs are generated independently.

## Privacy, authority and rollback

Strict UTF-8 JSON rejects duplicate keys (including escaped equivalents), unknown nested keys, nonfinite values, excessive depth, oversized bodies and unsupported versions. The server repeats a conservative secret/path/URL/entropy scanner over summaries and model explanations. The native client performs consent, category projection, preview and its own preflight before a request is sent. Code excerpts, fixtures, simulation/scenario fields, arbitrary upstream/model/system/tool controls and query credentials are not accepted. Bearer authorization is an opaque 256-bit token checked by keyed digest against D1; no cross-account identifier is accepted from the client.

Cloudflare egress is one fixed HTTPS Anthropic Messages endpoint with redirects forbidden. Only bounded real Haiku 5.5 output with one text block, allowed thinking blocks, `end_turn`, matching model, first-party `request-id`, valid usage and advisory verdict can produce a 200 analysis reply. A model allow never creates host permission. No upstream error bodies are returned, logged or retried.

Disable `CLOUD_ANALYSIS_ENABLED` and deploy the affected environment for emergency rollback; verify capabilities reports false and analysis returns 503. Device revoke is authenticated and only affects its own device. Operator digest-only D1 revoke can set `revoked_at` for a device/account without a public admin route. For server-key exposure, disable inference first, rotate through the Anthropic Console and runtime secret store, then re-enable only after an explicit synthetic billed smoke. For digest-secret exposure, rotate the secret and reissue invitations/credentials. Restore application code with Wrangler's version rollback only after checking schema compatibility; migrations here are additive. A code rollback must never undo authoritative SQLite accounting.

## Tests

`npm test` runs inside workerd on Node 24 with real D1 and SQLite Durable Object bindings and a fake fetch transport restricted to the Anthropic URL. It covers concurrent invitation redemption, optional caps and uncapped mode, durable replay across restarts, the credential lifecycle, deletion recovery, outbox failures, upload/deadline/concurrency handling, structured-output provenance, strict parsing and privacy seeds. No test makes a billable request; `scripts/hosted-smoke.mjs` exercises a deployed environment.
